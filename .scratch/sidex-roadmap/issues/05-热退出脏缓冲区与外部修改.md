# 05: 热退出：脏缓冲区与外部修改

**What to build:** 未保存的编辑缓冲区随会话持久化，重启后原样恢复且不弹保存对话框；若文件在应用外被修改，启动时提示选择保留或重新加载。

**Blocked by:** 03 会话恢复：目录标签、文件标签与导航历史

**Status:** done

- [x] 有未保存内容的文件重启后内容与脏状态保留
- [x] 新建未命名文件也能恢复
- [x] 外部修改时出现明确提示并可选保留或重新加载
- [x] 正常保存或关闭后不残留恢复数据

## Comments

- 2026-11-06：SideX 桌面端关闭 web 默认的自动保存（`files.autoSave: off`），否则文件在 1 秒后自动保存，热退出没有可恢复的脏缓冲区。
- 普通文件的脏缓冲区改为自管理备份：工作集持久化时记录脏标记、磁盘 `mtime` 和文件内容（单文件上限 5 MB），写入 `sidex.directory.fileBackups`；启动/切换标签时先把备份内容写回文本模型，再恢复光标与滚动。未命名文件使用 untyped input 的 `contents` 恢复。
- 启动后若模型仍为脏且磁盘 `mtime` 与保存时不同，显示粘性警告通知，提供「保留我的更改」与「从磁盘重新加载」；重载调用 `ITextFileService.revert`，成功后备份随之清除。
- 保存、重载、关闭标签都会触发工作集与备份重写，正常关闭后不残留恢复数据。
- 验证：`npx tsc --noEmit`、`npm run build` 通过。通过 WebView2 远程调试实际验证：脏文件重启后内容与脏状态保留（内容为 `fourth dirty content`）；未命名文件 `untitled content` 恢复且保持脏状态；外部修改后启动出现「保留我的更改 / 从磁盘重新加载」通知，点击重载后内容变为磁盘内容且脏状态清除。
