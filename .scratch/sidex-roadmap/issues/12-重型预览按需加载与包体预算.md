## Comments

- 2026-11-06：PDF 预览改为按需加载。`pdfPreviewEditor` 不再静态引入 `pdfjs-dist` 与 `pdf_viewer.mjs`，仅在编辑器实例创建时依次动态加载内核、设置 `GlobalWorkerOptions.workerSrc` / `globalThis.pdfjsLib`、再加载 viewer 与 `pdf_viewer.css`；`setInput` 等待运行时就绪后再读取与渲染。删除不再需要的 `pdfjsSetup.ts`。
- Mermaid 已经是 `import('mermaid')` 动态加载，HTML 预览基于 webview + iframe、无重型依赖，均无需改动。
- 构建产物（`npm run build` 的 `postbuild` 统计）：JS 17.25 MB，CSS 570.08 kB，字体 624.50 kB，总计 18.42 MB（改前基线 JS 17.32 MB / 总计 18.49 MB）。PDF 依赖已拆成独立懒加载块：`pdf_viewer` JS 138.34 kB、`pdf` JS 334.80 kB、`pdf_viewer.css` 111.52 kB；Mermaid/ELK 及图示仍为独立懒加载块。`index.html` 只预加载 `nls.js`，启动静态导入图约 10.7 MB。
- 未达到总计 16 MB 的原因：总量包含全部按需块，固定大头为 `nls.js` 5.82 MB（含 VS Code 全量 NLS 与 core 模块）、`workbench.common.main` 3.87 MB、Mermaid 布局 `elk` 1.41 MB 与各图示约 2 MB；进一步下降需要拆分 nls/workbench 或裁剪 Mermaid 图示，超出本 issue 的预览懒加载范围。
- 验证：`npx tsc --noEmit`、`npm run build`、`cargo check` 通过；`npm run tauri dev` 启动冒烟通过（1543ms，无错误，启动日志未见 PDF/Mermaid 块）。PDF 运行时加载顺序用 Edge 对构建产物做了验证：先加载内核并挂到 `globalThis.pdfjsLib`，再加载 viewer 与 CSS，`PDFViewer`、`EventBus`、`PDFLinkService`、`FindController` 均可实例化；完整 PDF 打开、Mermaid 与 HTML 预览建议人工快速确认。
