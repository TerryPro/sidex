# 文件列表采用三档查看模式与每标签独立排序

Status: accepted（2026-11-08）

SideX 的文件列表长期只有「详细信息」一种排布，排序也只有一个全局状态，切换目录标签会把上一个标签的排序带过去。参考 Windows 资源管理器的做法，我们决定：

- 查看模式固定为三档：**详细信息**、**列表**、**图标**。图标模式是固定尺寸的网格卡片，不提供超大/大/中/小图标与平铺。
- 排序由列头点击、标题栏「查看 / 排序」按钮与右键菜单共同驱动，键为名称、修改日期、类型、大小，方向为升序/降序。
- 排序与查看模式按目录标签各自保存；新标签继承最近一次使用的状态。
- 「显示文件扩展名」只影响名称显示，不改变重命名、打开与类型列。
- 不做分组依据（按类型/日期分组）。

## Consequences

- 图标模式需要独立的网格虚拟化：列数随宽度变化，键盘上下按整行移动，左右按单个条目移动。
- 查看状态从单键 `sidex.directory.sort` 迁移为「每标签记录 + 默认值」两个键，旧键只作为首次升级的回退。
- 扩展名开关是全局机器级状态，不进入设置项，避免为一处显示开关增加配置面。
- 分组、平铺与多尺寸图标留给后续版本；它们会同时改动虚拟滚动、选择范围和行高计算，不适合与本次一起做。

## Considered Options

- 完整复刻 Windows 的八种查看方式：三套图标尺寸、平铺与列表各有独立行高，测试与维护成本明显超出收益。
- 只增加「列表」一种模式：改动最小，但解决不了「一屏扫图找文件」的需求。
- 保持全局排序：实现最简单，但切标签时排序串台，与目录标签「各自独立现场」的既有模型冲突。
