# SideX 现状与下一步开发方向

> 盘点时间：2026-11-04。依据当前代码与最近裁剪提交；本日已彻底移除 LSP，改为原生语法高亮、折叠与大纲。
> 说明：本文基于代码与构建产物整理，未做完整 UI 逐项手工回归。

## 一、结论

| 项目 | 判断 |
| --- | --- |
| 产品骨架 | 已成立：目录标签 + 文件列表 + Monaco 编辑 + 预览 + WASM 扩展 + 原生语法（高亮/折叠/大纲） + 基础终端 |
| 当前最大缺口 | 文件管理器主链路不完整：单击预览、右侧属性、右键与文件操作、地址栏编辑、会话恢复尚未落地 |
| 下一步主线 | 先完成「文件浏览 + 文件管理」闭环，再做目录隔离与会话恢复 |
| 暂缓方向 | Git/SCM、调试、任务、测试、笔记本、远程、市场、多窗口、AI 聊天 |

## 六、下一步开发方向

### 6.1 推荐主线

**先做「文件管理器闭环」，暂不深化语言/扩展能力。**

理由：目录标签与 Monaco 编辑已经可用，但单击预览、属性、右键、文件操作、地址栏、会话恢复这些「资源管理器基本盘」仍缺失；继续做语言能力会偏离产品定位。

## 八、LSP 移除结果（已实施，2026-11-04）

### 8.1 结论

**LSP 已彻底移除。** 产品只保留关键字高亮、折叠与大纲，不再启动任何语言服务器，也不再接收语言诊断。

理由：

| 原因 | 说明 |
| --- | --- |
| 需求错位 | 产品只需要关键字高亮、折叠、大纲；LSP 的主要价值是补全、跳转、诊断、重命名、重构 |
| 复杂度高 | LSP 引入外部进程、服务器安装与版本管理、项目根解析、多目录实例池 |
| 故障面大 | 服务器未安装、启动失败、根目录错误都会直接影响编辑体验 |
| 多目录未稳定 | 目录标签与编辑器隔离尚未完成，LSP 单根假设会放大问题 |

### 8.2 已删除

| 项目 | 处理结果 |
| --- | --- |
| LSP 前端服务 | `sidexLspService.ts` 已删除，`workbench.common.main.ts` 不再注册 |
| LSP Rust 后端 | 删除 `commands/lsp.rs`、`crates/sidex-lsp`、`lib.rs` 中的 LSP 状态与命令注册 |
| WASM 宿主内 LSP/tsserver | `extension_wasm.rs` 删除通用 LSP 客户端、tsserver 进程、文档同步与诊断采集 |
| 语言扩展 | 删除 C++、Go、Python、Rust、TypeScript、Markdown 六个扩展与 `sidex-language-client` |
| Merge Conflict 扩展 | 已删除 |
| WASM 语言 Provider | 仅保留 `documentSymbol` 与 `foldingRange`；补全、悬停、定义、引用、重命名、代码操作、签名帮助、内联提示、格式化、诊断注册全部移除 |
| 诊断 | 不再有语言诊断来源，Problems 面板保留但不再由语言服务填充 |
| 依赖锁 | `Cargo.lock` 与 `src-tauri/Cargo.lock` 已同步，无 `sidex-lsp` / `lsp-types` 残留 |

### 8.3 保留能力

| 能力 | 实现 |
| --- | --- |
| 关键字高亮 | TextMate 语法 + Rust 分词，保持现状 |
| 折叠 | Monaco 缩进折叠 + 语言配置 `folding.markers` + Rust 原生折叠（大括号语言与 Markdown 标题） |
| 大纲 | Rust 原生符号提取 `syntax_get_document_symbols`，覆盖 Rust、Python、Go、TypeScript/JavaScript、C/C++、Java/C#、Markdown；WASM 扩展仍可提供符号与折叠 |
| 自定义编辑器 | `csv-editor` 等 WASM 自定义编辑器保留 |
| 搜索、预览、终端 | 不受影响 |

### 8.4 代价

| 失去的能力 | 影响 |
| --- | --- |
| 补全、悬停、跳转、引用、重命名 | 不再提供，需要自行打开文件查找 |
| 格式化 | 不再提供语言服务器格式化 |
| 语言诊断 | 不再显示语法/类型错误 |
| 大纲精度 | 正则为启发式，复杂嵌套、匿名结构与宏展开无法覆盖；无匹配规则的文本语言大纲为空 |

| `cargo check -p sidex` | 通过（仅存量 dead_code 警告） |
