# 04 工作区与项目语义移除

## 背景

产品模型是「目录标签 + 文件列表」，不是 VS Code 的「工作区/项目」。需要移除打开工作区、保存工作区、添加文件夹到工作区、Workspace Trust 等命令与 UI。

## 执行结果（2026-11-04）

| 项目 | 实际改动 |
| --- | --- |
| 工作区贡献 | `workbench.common.main.ts` 移除 `contrib/workspace`、`contrib/workspaces` import |
| 工作区 UI | `src/vs/workbench/contrib/workspaces/`、`src/vs/workbench/contrib/workspace/` 已删除 |
| 工作区编辑服务 | `workbench.web.main.ts` 移除 `workspaceEditingService` 注册，打开目录仍使用内部目录集合 |
| 文件菜单 | 删除「Open Workspace from File…」「Add Folder to Workspace…」「Save Workspace As…」「Duplicate Workspace」菜单项 |
| 命令面板 | `OpenWorkspaceAction`、`OpenWorkspaceConfigFileAction`、`SaveWorkspaceAsAction`、`DuplicateWorkspaceInNewWindowAction` 已删除；`AddRootFolderAction`、`RemoveRootFolderAction` 改为内部动作，不再 `f1` 暴露 |
| 右键菜单 | Explorer 右键移除「Add Folder to Workspace」「Remove Folder from Workspace」 |
| 空视图 | 「打开文件夹」欢迎按钮统一指向 `OpenFolderAction` |
| 保留 | `IWorkspaceContextService`、`IWorkspaceEditingService` 等内部服务保留，用于目录集合与最近目录 |

## 原始实施清单

- [x] 移除 `workbench.common.main.ts` 中 `contrib/workspace`、`contrib/workspaces` 的 import。
- [x] 删除 `src/vs/workbench/contrib/workspaces/`。
- [x] 删除 `src/vs/workbench/contrib/workspace/` 的信任 UI 与命令。
- [x] 删除 `workbench.web.main.ts` 中工作区编辑服务注册，确认打开目录仍可用。
- [x] 删除命令：打开工作区、保存工作区为、添加/移除文件夹、复制工作区、Workspace Trust 管理。
- [x] 清理工作区相关菜单项与用户入口。
- [x] UI 文案统一为「打开文件夹」「最近文件夹」，命令面板不再出现工作区入口。
- [x] 清理 `workbench.action.openWorkspace`、`saveWorkspaceAs`、`addFolderToWorkspace` 的用户入口。

> 保留说明：`.code-workspace` 文件类型与 `vscode.openFolder` API 兼容逻辑保留，但不再有用户入口；工作区内部服务仅用于「已打开目录集合」。
